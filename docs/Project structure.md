# Project Structure

> Examples use JavaScript, but everything applies equally to TypeScript. The only difference is the file extension (`.ts` instead of `.js`), that imports do **not** include the extension, and that paths use `src/frontend/ts/` instead of `src/frontend/js/`.

Nibula ships a fixed layout so you always know where to put your hands. Inside these folders you're free to organize as you like — subfolders in `components/`, `modules/` and `api/` are all fair game.

## The tree

```
your-project/
├── .eleventy.js          # Eleventy configuration
├── nginx.conf            # nginx site file
├── package.json
├── out/                  # Build output — never edit, never commit
└── src/
    ├── backend/          # REST API — see docs/Backend.md
    └── frontend/
        ├── assets/       # Images, fonts, brand files
        │   └── brand/    # Favicons, logo etc
        ├── components/   # Reusable .njk fragments and .md content
        │   └── global/   # Header and footer, included in every page
        ├── data/         # site.json and pages.json
        ├── hosting/      # .htaccess and web.config
        ├── indexing/     # llms, robots and sitemap templates
        ├── js/           # global.js, modules/, pages/
        ├── layouts/      # base.njk — the HTML skeleton every page extends
        ├── routes/       # One file per page
        └── scss/         # _root.scss, _global.scss, modules/, pages/
```

## Where things happen

| I want to... | Go to |
|---|---|
| Add a page | `nib cli` → creates the files in `routes/`, `scss/pages/`, `js/pages/` |
| Write the content of a page | `routes/` |
| Build a reusable block of markup | `components/` |
| Write long prose in Markdown | `components/` — see docs/Components.md |
| Change the header or footer | `components/global/` |
| Style one page | `scss/pages/` |
| Style every page | `scss/_global.scss` |
| Define a variable used across the site | `scss/_root.scss` |
| Run a script on one page | `js/pages/` |
| Run a script everywhere | `js/global.js` |
| Change the site name, URL, author | `data/site.json` |
| Change a page's SEO | `data/pages.json` |
| Edit the HTML `<head>` | `layouts/base.njk` |
| Give one page a different skeleton | `layouts/` — add your own, see docs/Components.md |
| Add an API endpoint | `backend/api/` |

## Two folders worth a note

**`out/`** is generated by every build. Editing anything in it means losing the change the next time you run `nib run` or `nib build`. Always edit the source in `src/` — including `.htaccess` and `web.config`, whose sources live in `src/frontend/hosting/`.

**`data/`** feeds the build but is never published: it holds the full page map, including pages you marked `noindex`, so it stays out of the output on purpose.

## What you can rearrange

Subfolders are allowed wherever content is yours to organize:

- `components/` — nest as deep as you like; includes take the path relative to `components/`, and so does the `markdownPath` filter
- `scss/modules/` and `js/modules/` — same idea, remember to update the relative import paths
- `layouts/` — extra layouts alongside `base.njk`; routes pick one by filename
- `backend/api/public/` and `protected/` — subfolders become part of the URL

The folders in the tree above are the part to leave alone: paths are wired into `.eleventy.js`, the build scripts and the assistant, so renaming one breaks the build.
